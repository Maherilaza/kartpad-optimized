# KartPad 0.5.0 source delivery candidate

The coordinated delivery identifies the compilation source separately from later packaging work. Android code132 and Apple build56 were compiled from clean `e7877946ebfe04782ecd058116c754e3baa3dd87`. The core snapshot includes that parent commit and all four recursive maintained runtime pins. Its 6,874 tracked files reproduce the source fingerprint embedded in the APK and IPA. The Mac package records the same compilation commit.

`SOURCE-MANIFEST.json` binds every delivery member by SHA-256 and size and records the three candidate artifact hashes. This is a source-delivery candidate, not release approval. Runtime acceptance and the final public archive/notices audit remain separate.

The dependency sources are retained byte-for-byte from the verified 0.4.24 delivery. Old prepared application runtimes, old core snapshots and old release scripts are excluded. The original dependency manifests retain their original identities; an old release name in a dependency document does not identify the new app source.

To rebuild:

1. Extract `KartPad-core-source.tar.gz` and use `restore-source-git.py` with `metadata/kartpad.json` to restore the parent and recursive runtime Git identities. Follow the core's Android and Apple build instructions with your own supported game data and the documented SDK/toolchain versions.
2. Use the supplied CMake, Dawn, Maven and Dolphin dependency manifests to locate the accompanying source archives. Their recorded hashes remain authoritative. The profile-tool and Dolphin snapshots include their own restoration metadata.
3. Android uses Dawn base `13abc3bc8ea2d3c2050f9e77a12d012108ceee24` plus both patches under `prototypes/stabilization/dependencies/`. Follow `build-dawn-android.sh`, `pin-dawn-version.py` and `package-dawn-android.py` from the core. The source identity is `b0fd045b0a694eb07ac3fcf0d741f8697b935856`; the verified production binary archive SHA-256 is `c6b4efde6de30f341c46b65a1679914142059b360856d38e32f40dd55cae7fc1`. Populate dependency Git checkouts at the recorded revisions before running the dependency verifier. No external Vulkan validation layer is required.
4. Apple retains its separately pinned Dawn package and build configuration. Do not substitute the patched Android library into an Apple build.
5. Regenerate the private translation/profile inputs from your own game data. Generated game translation, disc images, saves, private traces and signing identities are not included. Use your own signer for installation; it cannot update an app signed by a different identity in place.

The archive carries source inputs and rebuild instructions, not a claim that a different compiler or SDK will produce identical binary bytes. Binary identity checks apply to the exact reviewed candidates. The existing dependency reconstruction documents remain useful for dependency layout; their old application composition descriptions do not describe build56, which was rebuilt from the current maintained source.
