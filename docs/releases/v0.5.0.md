# KartPad 0.5.0 — release draft

Status: Android code135 installed; first-entry Retro vehicle thumbnails verified. Apple build59 IPA/Mac ZIP packaged but not installed. Owner acceptance and final release preparation remain pending. Not published.

[Current fixes, evidence and unresolved reports](v0.5.0-readiness.md).

KartPad 0.5.0 brings an auto-accelerate switch, Android controller assignment
fixes, and corrections to rendering and graphics startup. The latest candidates
are code135/build59. Earlier code134/build58 lacks the black-thumbnail repair
and must not be published as containing it.

Changes in the candidate:

- Generated vehicle thumbnails and other framebuffer-to-texture copies retain complete draws while shaders compile, including copies spanning a full staging buffer. This fixes two independently reproduced paths that could permanently capture missing pixels.
- **Auto-accelerate can be turned off.** On Android, open Controls → Touch Control Settings → Auto-accelerate. OFF restores ordinary press, hold and release behavior for A; ON keeps the one-second hold-to-latch behavior. The choice is saved. iPhone and iPad also have the persistent opt-out.
- Android controller remapping uses a consistent input route. Choosing Unassigned stays unassigned, and the native and older controller settings screens agree on player assignments.
- Renderer fixes cover stale vertex data, format and primitive changes, index bounds, incomplete primitives, scaled framebuffer copies, delayed readback callbacks and full staging buffers. Operations that exceed a single fixed staging budget are rejected before writing outside it.
- Cleanup after failed or partial startup checks whether each ImGui backend initialized, preventing a secondary null-pointer crash that concealed the original failure.
- Android startup handles missing optional Vulkan debug functions and a separate SwiftShader configuration failure. A failed graphics initialization retains a useful error instead of a generic native abort.
- Startup recipe replay is capped at 128 pipelines with one speculative compiler on Android and Apple platforms. Framebuffer blits select the actual RGBA/BGRA destination format. Android shader-cache reuse is also bounded to reduce repeated startup work. This is not a measured claim of faster warmed races on every handset.
- Ghost export reports invalid records instead of silently treating all validation failures as an empty license.

The corrected source passes shared regression and sanitizer tests. With Dawn validation enabled, the old renderer reproduces the exact iPad framebuffer-copy crash; the corrected renderer passes the same test, independent pixel comparisons, scaled/offscreen readbacks, capacity splits and frame-worker execution. Bounded prewarm also completed from the bundled recipe database with an empty local Dawn cache on Mac. These are host checks, not physical iPad gameplay acceptance. Build58 passes the physical-iOS build, package, symbol and signature checks and is installed on the owner’s iPad with all 30 freshly backed-up save/settings files unchanged. That build58 installation remains unchanged; the newly packaged build59 contains the additional texture-copy fix. Owner gameplay confirmation remains pending.

The owner reports that one existing iPad Retro license still returns serial mismatch (22005), while the second reaches versus worldwide. This old-license behavior predates build58; the persisted identity is unchanged. Retro menu pacing remains unresolved.

Known unresolved reports include S24 and other device-specific geometry corruption, PowerVR capability rejection, warmed slow-device performance, Mac Wii Remote/Classic Pro delays, and the reported Original ghost-discovery case. The new Red Magic 11 Pro report was submitted from Android build65 and has not been reproduced on this candidate. No issue is closed solely because it resembles a corrected source defect.

No game-data files or private signing identity are included. Existing installation, data-preservation and platform requirements still apply; see the platform installation guides supplied with the final assets.
